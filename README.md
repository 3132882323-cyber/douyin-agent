> **让每一笔预算有目标、每一次调整有依据、每一个结果能复盘。**

店策 Agent 是一套面向抖音电商商家的本地优先智能经营系统。

它把抖店、巨量千川、千川乘方、直播、商品和内容数据放进同一个经营大脑：先核对店铺与账户，再算清退款后的真实利润，识别今天最重要的经营问题，并给出有证据、有边界、有验收时间的下一步。

面对千川乘方，店策 Agent 不替平台重复分配流量，而是补齐商家真正需要的经营控制：经营目标、保本线、成本账本、商品资格、风险边界、策略沙盘和持续自动评估。除“L0 只读 + A1 影子决策 + A2 本机模拟试运行”外，内部商业版已接入首条 L3 生产能力：在官方 OAuth、可信计划快照和短时人工授权同时有效时，只允许对单个乘方父计划降低预算，并由官方接口立即回读。公开社区源码不包含商业生产写入模块。

| 看得全 | 算得清 | 排得准 | 控得住 | 记得住 |
| --- | --- | --- | --- | --- |
| 汇总店铺、商品、直播、投放与内容 | 计算保本线和退款后利润 | 每天只突出一个优先动作 | 建立授权、额度、回读和止损边界 | 沉淀每家店自己的经营规律 |

**它不是又一块展示数字的看板，而是站在商家利润一侧，帮助团队看懂生意、排定动作、守住风险并沉淀经验的经营 Agent。**

最新工作台按三条主线做了减法：商品经营只展示商品卡，内容素材只展示素材卡，直播经营统一管理直播数据、全部投放计划、自动投放、受控执行和操作回读。商品卡背后仍用稳定商品 ID 串联货架、直播、素材、千川、库存和售后证据，不按同名猜测；详细依据按需展开。

> **v4.14.9 生产写入绑定租约与结果归因收口：** 店铺—账户绑定租约覆盖目标解析、OAuth、双预读、单次 POST 与回读；解绑、重绑或快照失效会在官方 I/O 前拒绝，且不消耗授权。GET 观察值不再冒充本次请求成功，歧义结果继续冻结并只读对账；首次真实写入按五步引导完成。由于官方接口未提供 CAS，当前仍只适合单机、单操作者、小预算灰度。

> **v4.14.8 乘方受控生产写入：** 只允许从可信官方快照选择一个父计划，将预算下调不超过 20%；加预算、批量修改、启停、删除、ROI 调整和网页点击兜底全部关闭。任何响应歧义都会冻结后续写入并要求官方只读对账。
>
> **v4.14.7 无 ID 计划失败关闭：** 平台页识别不到稳定计划 ID 时，系统明确提示重新同步，只允许查看诊断；不会再按显示名称生成可变任务，也不会被当前选中账户“代领”。
>
> **v4.14.6 计划任务连续性：** 同一千川计划只保留一个可变任务身份；旧编号只能作为服务端校验后的迁移入口，不能绕过新鲜度、账户和店铺检查。跨日结案不会被历史“处理中”状态复活，计划卡结案必须填写结果说明，并使用当前合同指纹提交。
>
> **v4.14.5 绑定与首用可信：** 浏览器页面只能发现账户，不能在正式权限注册表初始化后自动授予店铺关系；目录、选择和读取共用同一绑定租约。欢迎页只有在当前店铺存在 10 分钟内的抖店数据时显示就绪，千川数据不再冒充抖店已巡检。

> **v4.14.4 稳定性收口：** 数字平台错误码不再破坏同步状态；损坏记录、过期授权和取消巡店都有明确恢复入口。效果回读缺少完整指标定义、版本或周期时只会要求补读，不会产生止损结论。同名计划、跨模式计划和直播/商品计划互不合并；macOS 验收与 Windows 离线升级统一执行版本、扩展身份、进程归属和回滚证据校验。

> **v4.14.3 认证连贯性修复：** 页面同步 POST 与工作台 GET 统一绑定同一个受信扩展身份。认证心跳不再复用聚合型 `/system/status`，而是读取不访问经营数据的 `/auth/status`；回执必须同时匹配当前扩展 ID、扩展版本和 Agent 要求版本。已经打开的工作台在重新聚焦或运行时恢复后会自动轻量复核，并带冷却和 single-flight 防止重试循环；只有完整双阳性回执才重新开放写入。

> **v4.14.2 页内同步与五层恢复：** 系统分别核对 Agent、磁盘扩展、浏览器 Worker、扩展工作台文档与平台采集组件。旧工作台由共用恢复器在失效上下文后有界刷新；已打开的抖店/千川页会补上页内助手，但不会后台自动采集。连接成功和数据同步成功使用不同回执，只有本机 Agent 真正保存新快照后才显示“当前页同步成功”。

## AI 协作：连接模型，不交出投放控制权

在工作台的“系统与数据 → AI 分析连接”中，可以连接 GPT、DeepSeek、千问 / 阿里云百炼、智谱 GLM、腾讯混元 TokenHub、豆包 / 火山引擎方舟、OpenAI 兼容服务或本地模型。千问默认 `qwen-plus`，GLM 默认 `glm-5.2`，混元默认 `hy3`，豆包默认使用方舟当前公开工具调用模型；也可填写当前账户实际开通的模型或 Endpoint ID。云端连接必须先查看发送预览并明确同意；连接测试只发送固定合成数据，不会发送店铺数据，也不会保存测试配置或密钥。

千问 / 百炼的地域地址、WorkspaceId 和模型开通方式以[阿里云百炼 OpenAI 兼容接口文档](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)为准；不同地域的 API Key 不混用。

智谱使用[GLM OpenAI 兼容接口](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)；腾讯混元使用新版 [TokenHub API](https://cloud.tencent.com/document/product/1823/130078) 和 `hy3`，国内、国际与备用站点的 Key 不跨站复用；豆包使用[火山方舟官方推理入口](https://www.volcengine.com/docs/82379/1795150)。三个官方预设都固定校验 HTTPS 域名和 API 根路径，不接受外观相似的第三方地址。

真正运行影子分析时，Agent 只发送匿名店铺/账户引用、单计划聚合指标、数据时间、质量分和本地风控阈值。Cookie、Token、API Key、真实店名、订单明细、网页全文、截图和素材原文不会进入模型上下文。Windows API Key 由 DPAPI 保存，macOS 使用登录钥匙串；页面永不回显已保存密钥。

模型输出必须通过严格的 `DecisionProposalV1` 合同和本地二次校验，且永远标记为 `can_execute=false`。AI 可以建议继续观察、降预算、暂停或恢复，但不能确认授权、创建计划、提交预算或调用浏览器执行器。真实操作仍需独立的店铺/账户绑定、最新页面回读、人工授权、额度限制和结果回读。

> **发布状态说明：** `本地可用` 只代表本机诊断与受监督执行链路可工作；只有生产 Ed25519、当前平台完整代码签名与发行公证，以及当前扩展的官方商店 ID、请求来源、安装来源和目标版本全部通过，系统才会显示 `可公开发行`。Windows 验证 Authenticode，macOS 验证 Developer ID 与 Gatekeeper；当前缺少任一证据时会明确显示 `本地可用 · 发行受阻`。

> **抖店服务市场路线：** 浏览器扩展仅用于 `local/internal` 版本，不作为服务市场审核版核心。服务市场版通过官方 OAuth、Open API 和 HTTPS 多租户工作台运行，并在代码层强制关闭网页采集与 DOM 执行。当前只完成第一批安全与适配骨架，尚不代表已获得平台资格或可以上架。详见 [抖店服务市场版改造与部署边界](MARKETPLACE_DEPLOYMENT.md)。

## 30 秒项目介绍

做抖音电商的人都知道，最累的不是看不到数据，而是数据散落在抖店、千川、直播和素材后台；看完之后，仍然不知道今天先做什么，也不知道 ROI 达标以后究竟赚没赚钱。

所以我做了 **店策 Agent**——一个专门服务抖音电商和千川乘方的智能经营大脑。

它会把店铺、商品、直播、投放和内容放进同一条经营链路，帮你核对账户、算清保本线、识别增长瓶颈，并把今天最应该处理的一件事放在最前面。

对于千川乘方，它不会盲目替平台调流量，而是先帮助商家确定经营目标和风险边界，通过本地 Agent 的 7 天影子自动评估验证建议；只有真实数据、正式授权和执行回读全部具备，才逐步开放更高等级的自动化。

**店策 Agent，让抖音电商从“看数据、凭经验”，走向“算利润、定策略、控风险、能复盘”的智能经营。**

## 为什么做这个项目

抖音电商真正稀缺的不是数据，而是把数据及时变成正确动作的能力。很多团队每天仍在多个后台之间切换、复制、判断和汇报：

- 数据散落在抖店、千川、精选联盟等不同页面，查看成本高。
- 运营看到指标，却不知道今天最该先处理哪三件事。
- 千川计划调整依赖经验，缺少统一的止损、观察和放量口径。
- 库存、投放、直播和货架各自优化，容易出现“流量放大但库存断货”。
- 日报花时间整理数字，却很难形成负责人、动作和验收标准。

店策 Agent 把这些重复工作组织成一条可追踪、可控制、可复盘的经营链路：

```text
网页读取与脱敏 → 经营诊断 → 下一步动作 → 人工授权
             → 受控执行 → 页面回读 → 效果复盘 → 店铺经营记忆
```

## 谁适合使用

| 角色 | 最关心的问题 | 店策 Agent 提供什么 |
| --- | --- | --- |
| 商品运营 | 哪件商品需要先处理 | 一件商品一张卡，集中显示状态、指标、风险和下一步 |

## 核心能力

### 1. 无 API 的手动全店巡查

- 复用用户已登录的抖店、千川和精选联盟网页，不读取 Cookie。
- 仅在点击“全店巡查”后运行，依次打开 18 类核心页面。
- 千川数据直接来自已登录的巨量千川后台，覆盖首页、商品推广、直播推广、直播大屏和视频库。
- 抖店店铺与千川账户使用两套匿名身份：本地 Agent 以随机密钥参与 HMAC-SHA256 计算，只保存不可逆的 `store_key` / `account_key`，不把明文店名、账号名称或平台原始 ID 写入快照、目录和日志。
- 同一明确店铺 ID 在抖店与千川页面会得到同一匿名店铺键；广告主 ID 只生成匿名账户键，绝不会直接冒充店铺身份。
- 只有明确店铺 ID 完全一致或官方 API 返回可靠映射时才自动关联；同名、模糊页面字段或单一低置信存储线索不会触发合并，工作台会要求用户人工确认。
- 身份密钥属于本地用户数据并随正式备份保留；清空本地配置或换机但不恢复密钥后，历史匿名键无法重新推导，需要重新识别和关联。官方 OAuth 为继续调用平台接口，必要的授权元数据只保存在系统加密凭据文件中，不进入经营快照、目录、报告或日志。
- 账号识别或全店巡查失败时，先访问一次目标千川标签页，再点击工作台右侧常驻的“同步千川”；系统优先读取最近访问的千川标签页，不校验历史账号，也不扫描其他页面。
- 千川入口使用官方根地址并保留旧首页回退；遇到 `ERR_FAILED` 或登录失效时停止采集并给出明确恢复提示，不再把浏览器错误页当作经营页面。
- 抖店与千川巡查使用彼此独立的后台标签页；标签页意外关闭时自动重建并重试当前任务，避免一个失效标签页导致全部千川页面连续失败。
- 巡查使用独立后台标签页，不操作用户原有页面；结束后自动关闭。
- 巡查结束生成数据体检单，展示账号、覆盖率、页面质量、读取行数和失败原因；失败页面可以单独重试，不必重新扫描全部页面。
- 对列表页尝试虚拟滚动并最多采集 5 页，同时记录行数、滚动次数和截断提示。
- 逐页记录成功、失败、数据质量和页面类型；失败页面自动重试一次。

### 2. 经营数据自动填写与本地历史

- 按 `数据源 + 页面类型` 保存快照，订单、商品、库存和计划数据不会互相覆盖。
- 默认保留 30 天脱敏历史，展示近 7 天核心指标变化。
- SQLite Schema 2 额外保存按店铺隔离的匿名商品/SKU/计划/素材实体、语义关系和指标观察；每个指标点绑定来源快照、千川账户、口径、频道和时间窗口。
- “商品信息”复合单元格中的商品 ID 会先在页面内按白名单提取，再在 localhost Bridge 中转为安装级 HMAC；原始商品 ID 不写入 JSON、SQLite 或备份。
- 跨日单品历史目前只用于展示“积累多少天、多少条有效观察”，不会直接参与自动放量；不同账户、不同 ROI 口径或未知时间窗口不得互相比较。
- URL 自动移除查询参数和 hash，页面原始 DOM 不会落盘。
- 数据只发送到本机 `127.0.0.1:8765`，不依赖云端数据库。

### 2.1 可选的巨量千川官方 OAuth

- 已取得巨量千川开放平台资质的用户，可在工作台“官方 API 授权”中连接应用。
- App ID 可公开配置；App Secret 不应发到聊天、写入代码或提交 GitHub，只在本机输入。
- Windows 使用当前用户 DPAPI，macOS 使用当前用户登录钥匙串，加密保存 App Secret、Access Token 与 Refresh Token。
- 公网回调只转发一次性授权结果到 `127.0.0.1:8765`，不保存 App Secret、Token 或账号密码。
- 每次授权都校验随机 `state`，授权会话 15 分钟后失效；授权码只用于一次 Token 交换。
- 官方 API 与浏览器页面采集共存，后续共用账号目录、经营数据模型和执行护栏。
- “千川账户中心 2.0”按账户展示授权有效期、广告账户映射、计划/报表/素材读取能力、最近同步与失败接口，不再让用户凭一排账号标签猜状态。
- 账户可设置本机别名、业务分组、只读同步开关和“纳入本地托管”；偏好文件只保存 HMAC 匿名账户键，不保存平台原始 ID 或 Token。
- 批量操作不会默认全选。用户必须显式勾选账户并先看影响预演；只读官方同步可确认后运行，定时启停、暂停和降预算仍只生成预演，不会提交平台。

### 2.2 每店独立的行业知识包

- 通用电商规则始终作为安全底层；服饰鞋包、美妆个护、食品生鲜三个首发行业包随 Agent 离线提供。
- 每家店只绑定自己的行业包，切换店铺后诊断、规则证据和界面状态同步切换，不会把 A 店经验带到 B 店。
- 自定义包先经过 SHA256、Ed25519、版本、有效期和规则结构校验，只进入“已安装”列表；用户明确点击“应用到当前店铺”后才生效。
- 行业包默认只能新增判断；只有通用包明确开放的规则才允许调整，不能覆盖、关闭或用去重键隐藏任何通用安全规则。失效、损坏或不兼容时只让该店安全回退通用包。
- 规则仍由本机确定性引擎执行，不要求连接 AI，也不会因选择知识包自动修改千川计划。

格式、制作、绑定和安全边界见 [行业知识包指南](INDUSTRY_KNOWLEDGE_PACKS.md)。

### 3. 千川计划调整方案

- 按计划明细给出止损、保持观察、素材优化和谨慎放量建议。
- 结合 ROI 目标、消耗门槛和转化表现展示判断依据。
- 使用“千川投手今日工作台”只展示必须处理、需要观察和具备放量条件的计划。
- 每条建议固定包含发现、判断、动作、调整范围、观察窗口和验收指标，并可加入今日任务持续跟踪。
- 预算方案以结构化操作草稿展示账号、计划 ID、当前值、目标值、证据时间和校验结果。
- 账号、计划 ID、当前预算、数据质量或新鲜度任一不足时，按钮会锁定并提示补齐数据；不会把未知预算错误兜底成暂停计划。
- “确认方案”只写入本机审计；只有启动执行前检查、完成页面回读并输入最终确认口令后，才允许受监督执行器降低单计划预算或暂停单个计划。
- 已确认方案会进入“投放影子执行”：用户在官方千川手动完成后主动标记，系统要求重新读取对应计划页面，并将最新预算与确认目标进行核验。
- 影子核验明确区分“等待人工执行、等待重新读取、回读已匹配、页面尚未变化、检测到其他修改”；用户声明不等同于插件执行成功。
- 隐私模式不会保存原始计划 ID；系统将其转换为不包含原文、跨页面稳定的本地代号，用于关联同一计划的确认方案和后续回读。

### 3.1 千川乘方安全自动投放（L0 + A1 + A2 模拟 + L3 受控生产）

**先看效果，不必等账户资料：** 打开“直播投放 → 千川乘方”，保持“演示环境”，点击“一键生成演示效果”。系统会用完全独立的合成数据，在约 1 分钟内展示“候选 → 模拟执行 → 模拟回读 → 效果卡”全流程。演示始终标注 `SYNTHETIC / DEMO_FIXTURE / platform_write_attempted=false`，不读取真实账户、不保存到真实运行时，也不会提交千川；点击“返回真实数据”即可退出演示。

1. 在“直播投放 → 千川乘方”同步当前页面，先核验店铺、千川账户、策略、指标口径和数据时间。
2. 完成经营建档：选择经营目标，按本店账本填写成本口径，并设置利润、预算、亏损、退款和库存边界。“生成保守草案”只补单次 5%、每日 1 次、120 分钟冷却等技术护栏，不猜预算、利润、退款或库存红线，也不覆盖已有值。
3. 点击“从同步数据补齐”可把当前作用域快照中的数据完整度、时间、总预算、ROI、消耗和订单带入表单；库存、履约、素材和已实现亏损仍按真实业务填写。官方精确记录缺少分子或分母时会把 ROI 标记为不可用，不沿用旧值。样本不足时不生成预算候选。
4. 开启 7 天影子自动评估后，本地 Agent 在同一个常驻进程里每 5 分钟评估一次；相同证据自动去重，只生成不可执行的降预算候选。
5. 建档、候选、评估与反馈按不可逆店铺作用域保存在 Agent 本地；浏览器仍保留兼容副本。空值与真实 `0` 严格区分，可随时停止或重置。

权限页会同时说明 L0 只读、A1 影子判断、A2 本机模拟和 L3 生产受控执行。A2 只验证自动化流程是否跑通，不等同于千川真实投放。内部商业版的 L3 当前只开放“单个乘方父计划降低预算”：先从新鲜的官方快照选择计划，再用官方详情核对原预算，目标预算必须低于原值且单次降幅不超过 20%，用户输入精确确认词后获得一次性短时授权，提交后再由官方详情接口回读。账户无权限、快照过期、预算已变化或回读不确定时不会继续写入；加预算、批量修改、创建/暂停/删除计划、ROI 改写和网页 DOM 点击仍全部关闭。标准计划原有受监督执行能力不等于乘方写能力。

#### 最快完成一次 L3 单计划降预算

1. 在巨量引擎开放平台完成当前商家的官方 OAuth 授权，并确认该应用、广告账户具有乘方预算更新权限。
2. 在“直播投放 → 千川乘方”执行一次官方同步；只有包含父计划预算、账户作用域和新鲜时间戳的可信快照会进入计划下拉框。
3. 在“受控生产写入”中选择一个计划并填写更低的目标预算，点击“生产预检”。预检只读，不会修改平台。
4. 核对调整前预算、目标预算和降幅，逐字输入界面生成的精确确认词，获得一次性短时授权。
5. 点击一次“执行官方写入”。系统只发送一次 POST；网络结果不明确时立即冻结，绝不自动重试。
6. 查看官方回读。只有目标计划的官方预算与目标值一致才标记为已验证；之后重新同步一次官方数据，作为下一次操作的新基线。

#### 资料齐全后，最快看到一次 A2 演练效果

1. 登录千川乘方并打开目标账户页面，在“直播投放 → 千川乘方”同步当前页。
2. 完成经营建档与止损边界，明确开启每 5 分钟同步；系统会自动把最新只读快照水合进当前作用域。
3. 开启 A1 影子评估。只有 ROI 低于保本线、当日消耗不少于 100 元且至少有 3 笔归因订单时，才生成“降低总预算”候选。
4. 在“A2 自动投放试运行”中加入 Agent 生成的唯一策略白名单、填写不高于经营上限的模拟预算帽，再人工审核候选。
5. 点击“执行本机模拟”和“完成模拟回读”，效果卡会显示调整前预算、目标预算、降幅、模拟回执、回读值和匹配结果；ROI、订单和利润不会被模拟或伪造。

若页面数据不足，控制台会精确指出缺少的作用域、证据、边界或样本量。L3 是否可用仍以当前应用权限、商家 OAuth、账户角色/白名单和官方接口返回为准；“界面已开放”不等于任意账户天然拥有平台权限。

#### 乘方生产写入安全协议

当前代码已经建立自动投放状态机、执行前协议、A1 影子循环和 A2 模拟适配器；内部商业版另包含基于巨量引擎官方接口的单计划降预算生产适配器。公开社区源码只保留安全降级入口，不包含商业生产写入实现。官方目录可见某项能力只代表能力发现，不代表当前应用或账户已经获准调用；每次 L3 写入仍必须通过以下闸门：

1. **经营对象唯一**：店铺、千川账户、乘方策略、指标口径和数据版本必须绑定为同一个不可逆作用域指纹。
2. **官方合同已验证**：公开文档中出现某项能力只算“能力发现”；必须继续验证当前应用、当前账户的权限、请求字段、返回字段和回读字段。乘方不提供 DOM 写操作兜底。
3. **策略边界完整**：显式填写单日预算、单次/单日调整幅度、单日动作次数、冷却时间、最大可承受亏损和单次授权有效期；系统不偷偷补默认值。
4. **影子观察达标**：至少 7 个有效观察日，建议有用率不低于 70%，回读成功率不低于 99%，且重大事故为 0。
5. **执行基础设施完整**：一次性执行占位、崩溃恢复、审计记录、紧急停止、官方 API 回读和人工对账缺一不可。官方接口没有幂等键时，可能已送达的 POST 绝不重试。
6. **每次动作重新授权**：动作必须绑定当前快照、版本号、目标值和短时人工授权；执行前再次检查数据是否在 10 分钟内、当日额度是否过期以及页面数据是否被其他人修改。
7. **先验收再观察**：提交后立即回读，并在 `2h / 24h / 3d / 7d` 复盘效果。首个生产协议只允许“降低单个父计划预算”；加预算、批量修改、ROI 调整、状态切换和商品池修改仍然保持关闭。

官方能力发现入口：[乘方与全域投放目录](https://open.oceanengine.com/tools/visual_debug.html?docId=1771195795225739)、[新建乘方直播计划](https://open.oceanengine.com/tools/visual_debug.html?docId=1871954016096256)、[计划预算更新](https://open.oceanengine.com/tools/visual_debug.html?docId=1841395352172800)、[创建全域调控任务](https://open.oceanengine.com/tools/visual_debug.html?docId=1825827435645963)、[千川乘方看数指南](https://school.oceanengine.com/page/academy-czkt?division_id=13001002)。这些链接用于核对能力方向，不代表本项目已经获得接口权限或通过生产验收。

生产适配顺序已经收敛为：可信官方快照选定父计划 → 官方详情读取旧预算 → 单计划降低预算 → 官方详情唯一回读 → 重新同步快照 → 2h/24h/3d/7d 经营观察。官方写接口没有可用的幂等参数，因此写请求一旦可能送达就不再重试；任何结果不明、读写不一致或恢复回读失败都进入 `UNKNOWN`，冻结后续生产写入并要求人工对账。具体契约记录见 [`bridge/chengfang_official_contract.py`](bridge/chengfang_official_contract.py)。

- 区分钩子吸引不足、点击后承接不足、数据积累期和可复制结构。

- 所有建议保持只读，不上传、删除或修改千川视频。

### 6.1 本店经营记忆：免费可用，按 scope 隔离

- 经营记忆保存在本机 `data/memory/operator_memory.json`，默认不上传云端，也不保存 Token、Cookie 或原始页面内容。
- 每条记忆都绑定“店铺 key + 千川账号 key”，切换店铺或账号后不会混用经验；没有确认当前店铺时，系统不会生成可复用结论。
- 支持四类记忆：经营事实、投放策略、团队偏好、动作结果；每条记录都有来源、置信度、更新时间和归档状态。
- 侧栏可直接新增、刷新和归档记忆；记忆只是决策证据，不会绕过数据可信度、预算额度或人工授权自动执行投放。
- 商业版可以在不改变本地安全边界的前提下扩展 365 天历史、跨店团队记忆、权限、检索和 AI 路由；基础的安全审计记忆保持免费，便于用户先体验闭环价值。

### 7. 三类业务工作台与每日经营报告

- 商品经营、直播经营、内容素材三类业务工作台；投放不再单独设重复入口。
- 岗位和班次会保存在当前浏览器；支持日常经营、开播前、直播中、下播复盘四套标准动作模板，并按天记录完成状态。
- 首页最多展示 3 个当日必做事项，降低信息负担。
- 任务支持待处理、进行中、待观察和已完成状态。
- 可立即生成 Markdown 日报，也可按设定时间使用最近一次缓存数据生成日报。
- 日志可选“默认经营日报、老板简报、运营交接日志、自定义模板”；没有特殊要求时直接使用默认模板。
- 自定义模板支持 `{{date}}`、`{{headline}}`、`{{summary}}`、`{{top_tasks}}`、`{{plans}}`、`{{inventory}}`、`{{scan_status}}` 占位符。
- 可连接飞书或钉钉自定义机器人，先保存并测试，再选择“生成并发送”；也可开启定时日报自动发送。
- 定时发送按“店铺 + 日期 + 平台 + Webhook 指纹”保存本地回执；失败按 1 分钟、5 分钟、15 分钟、1 小时、6 小时退避重试，已成功的平台不会重复发送，双平台只重试失败的一方。
- 日报会同步记录内容规律、投放执行和风险台账，方便老板查看与运营交接。
- **定时日报不会触发网页巡查**；需要最新数据时，运营先手动点击巡查。

## 产品原则与安全边界

| 原则 | 当前实现 |
| --- | --- |
| 用户掌控 | 所有网页巡查均由用户点击触发 |
| 默认不执行 | 普通确认不写页面；受监督执行器仅在二次确认和全部闸门通过后降低单计划预算或暂停单个计划 |
| 最少采集 | 只读取经营指标和允许的表格字段，不保存整页 DOM |
| 本地优先 | 快照、历史、任务和报告保存在用户电脑 |
| 建议可解释 | 每个建议尽量包含证据、动作、安全边界和验收指标 |
| 人工确认 | 草稿确认与真实执行分离；真实执行需要最终口令、60 秒单次授权和执行后回读 |

详细安全说明见 [SECURITY.md](SECURITY.md)。

## 快速开始

### 1. 下载项目

```bash
git clone https://github.com/3132882323-cyber/douyin-agent.git
cd douyin-agent
```

也可以在 GitHub 页面点击 `Code → Download ZIP` 后解压，但这是开发源码。Windows 普通用户应下载 `DianAgent-v*-windows.zip`；Apple Silicon Mac 朋友内测可使用 `DianAgent-v*-macos-source.zip`，首次安装需要 arm64 Python 3.10+ 和网络。真正无需 Python 的 Mac 包必须在 Apple Silicon Mac 上运行 `tools/macos/build_release.sh` 构建。

> **版本识别：** 官方公开包的 `/system/status` 显示 `public_community`，且 `commercial_modules_included=false`；内部商业包显示 `private_commercial` 和 `redistributable=false`；直接运行带本地私有模块的源码只显示 `developer_checkout`。公开构建会从经过二次扫描的临时净化源码生成，不会把本机乘方商业实现装进公开 ZIP。

### 2. 安装浏览器扩展

Windows 小白用户推荐下载完整 Release 包后，直接双击根目录的 `install_dian_agent.bat`。它会安装到 `%LOCALAPPDATA%\DianAgent`、设置登录自动启动，并同时打开浏览器扩展管理页和稳定的 `extension-current` 文件夹。由于 Chromium 的安全限制，最后仍需人工点击一次“加载已解压的扩展程序”并选择该文件夹。

macOS 13+ Apple Silicon 用户解压后双击 `install_dian_agent.command`。`macos-source` 首次安装需要 arm64 Python 3.10+ 和网络；`macos-arm64` 是无需 Python 的原生包。v4.14.0 为避免降级到有已知漏洞的安全库，不支持 Intel Mac。Agent 安装到 `~/Library/Application Support/DianAgent`，LaunchAgent 负责登录启动和异常恢复；Chrome / Edge 仍需人工加载其中的 `extension-current`。完整步骤见 [macOS 安装说明](README-MAC.md)。

项目提供两个浏览器包：

- 现代浏览器版：Chrome 116+、Edge、360 极速浏览器 X 等较新 Chromium 浏览器。
- 多浏览器兼容版：360 安全浏览器、QQ 浏览器、搜狗浏览器、联想浏览器等较旧 Chromium 内核。
- 两个版本点击扩展图标都会先打开轻量哨兵，需要深入分析时再进入独立经营工作台。

Windows 用户双击 `build_browser_packages.bat`，生成 `dist/dian-agent-modern` 和 `dist/dian-agent-compatible`。随后：

1. 打开浏览器的扩展管理页面。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择对应的生成目录。
5. 将“店策 Agent”固定到工具栏。

也可以在 Chrome/Edge 中直接加载项目的 `extension` 文件夹。安装成功后扩展详情应显示版本 `4.14.9`。首次安装会打开轻量引导页；打开抖店或千川后可直接使用右下角“店策页内助手”同步当前页，需要深入分析时再打开完整工作台。页内助手与工作台“同步千川”入口都可收起或关闭，并分别记住抖店、千川与工作台偏好；关闭后可从插件弹窗或工作台顶部“更多设置”恢复。360、QQ、搜狗等双核浏览器访问抖店和千川时必须使用“极速模式”，不能使用 IE 兼容模式。

完整浏览器矩阵和故障处理见 [浏览器适配说明](BROWSER_SUPPORT.md)。

### 3. 启用本地 Agent 自动启动

普通用户只运行 Release 根目录的 `install_dian_agent.bat`。安装器会把版本化程序安装到 `%LOCALAPPDATA%\DianAgent`，并通过无窗口启动器配置登录启动和保活；不要再运行 `bridge/enable_autostart.bat`，它只供源码开发调试使用。

源码开发者确实需要直接运行仓库代码时，才双击 `bridge/enable_autostart.bat`。开发模式使用独立任务名 `DianAgentDevKeepAlive`，不会覆盖正式安装的 `DianAgentKeepAlive`。

Windows 完整 Release 和 `macos-arm64` 原生包无需 Python。`macos-source` 源码内测包以及仓库源码开发模式需要 Python；其中 Mac 源码安装器会在程序目录创建隔离环境，不修改系统 Python。首次冷启动会显示明确进度，重复点击不会启动多个 Agent。

随后访问 <http://127.0.0.1:8765/health>。看到 `"status": "ok"` 即表示本地服务正常；完整数据库、磁盘与运行模式诊断需在已配对扩展的“系统与数据”页面查看，不再允许普通浏览器页面直接读取 `/system/status`。安装程序会同时创建登录启动快捷方式、登录计划任务和每 5 分钟检查一次的本地保活任务；二者都先进入 `%LOCALAPPDATA%\DianAgent\bootstrap\recovery_bootstrap.ps1`，因此维护工具目录正在原子切换或回滚时也不会丢失恢复入口。保活使用轻量 `/health/live`，只有连续失败三次、经过宽限期且再次核对端口所有者后才会重启，单次网络或磁盘抖动不会误杀 Agent。多重触发由互斥锁与任务单实例保护。若轻量哨兵仍提示未启动，可从 Windows 开始菜单运行“Repair Dian Agent”，它使用隐藏启动器检查并恢复服务，不会弹出 CMD 窗口。需要关闭自动启动时运行 `bridge/disable_autostart.bat`。

Mac 安装器注册当前用户的 `com.dianagent.agent` LaunchAgent，由系统完成登录启动和异常恢复，不使用 Windows 计划任务。修复时双击 `repair_dian_agent.command`；卸载时双击 `uninstall_dian_agent.command`，默认保留经营数据。

> 抖店和千川账号登录由平台官方登录页面及当前浏览器登录状态管理。本项目不会保存账号密码，也不会绕过验证码或平台风控。

### 升级与卸载

- macOS 当前没有正式在线自动更新；下载新版 Mac 包并再次运行安装器即可覆盖程序，数据默认保留。随后在 Chrome / Edge 扩展管理页点一次“重新加载”。修复和卸载步骤见 [macOS 安装说明](README-MAC.md)。
- Windows 完整安装包可覆盖安装，`data/config/knowledge/backup/logs` 会保留。
- 离线升级包可拖到完整 Release 目录里的 `upgrade_dian_agent.bat` 上；更新器无需 Python，会在解压前校验 Ed25519 发布签名、兼容范围和每个文件的 SHA-256。缺少签名、签名不可信或清单被修改都会直接拒绝，安装目录保持不变。离线协议从 `3.7.0` 起受支持；升级时使用 Release 自带的新启动器，真实健康后再用独立 `.release-tools-transaction.json` 更新维护工具并确认。该日志的事务 ID 与 stage/backup 目录后缀精确绑定；稳定 bootstrap 会在 `tools` 目标短暂缺失时恢复旧树。新版自检、真实启动或工具更新失败都会恢复旧程序指针、旧扩展并尝试重新启动旧版。
- 断电或强制关机留下待确认事务时，下一次启动会先尝试当前新版：只有本机 `/health` 返回完全一致的版本才会安全确认；真实启动超时后才自动恢复旧指针、旧扩展并重启旧版。回滚成功会返回专用状态，不会伪装成升级成功。
- 启动器每天最多进行一次保守维护检查，默认只预览。清理器永远保护当前版本、待回滚事务依赖版本、最近版本和初装 `app/<version>`；只有显式 `cleanup --apply` 且超过年龄阈值的孤立目录才会删除，Windows 文件锁会跳过并写入本地审计日志。
- 当前状态是“离线签名机制已就绪、生产信任锚尚未配置”，因此生产离线升级暂不可用；带 `development_test` 标记的测试包只供开发验证，不能作为最终用户产物。正式发布前必须离线生成生产密钥，只把公钥写入更新器，并完成 Windows 代码签名。
- 扩展始终加载 `%LOCALAPPDATA%\DianAgent\extension-current`；升级后如浏览器未自动刷新，在 `chrome://extensions` 点击一次“重新加载”。
- 卸载运行安装目录 `tools/uninstall_release.ps1`，可选择保留经营数据，或在精确路径确认后全部清除。
- 当前程序和扩展没有生产在线更新域名，工作台会如实显示“离线升级”；知识包自动更新不等于程序自动更新。

### 4. 开始第一次巡查

1. 在已安装扩展的浏览器中登录抖店；需要投放分析时再登录巨量千川，纯抖店用户无需连接千川。
2. 点击扩展图标，浏览器会打开独立经营工作台；重复点击会回到已有工作台。
3. 先打开抖店经营概览完成匿名店铺识别并选择当前店铺，再点击“全店巡查”。没有千川账户时只同步抖店关键页面；需要投放分析时，再访问目标千川页面并点击“同步千川”，无法可靠关联时按提示人工确认。
4. 直接在工作台查看今日三件事、千川建议、库存风险和直播/货架分析。
5. 在策略设置中填写 ROI 目标、消耗判断门槛和低库存阈值。

已申请官方 API 的用户还可以展开顶部“官方 API 授权”，在本机填写 App Secret 后点击“授权千川账号”。授权成功后，开放平台的“授权管理账号”列表才会出现对应账号。

## MCP 接入

本地 Agent 可以把严格脱敏、带时效与账户绑定的经营上下文提供给支持 MCP 的 AI 客户端。`v4.7.0` 起 MCP 使用“建议专用安全配置”：不再对外开放原始快照、设置读取、任务修改、授权、确认或执行工具。

```json
{
  "mcpServers": {
    "dian-agent": {
      "command": "python",
      "args": [
        "C:\\path\\to\\douyin-agent\\bridge\\server.py"
      ]
    }
  }
}
```

### 可用工具

| 工具 | 作用 |
| --- | --- |
| `get_ai_context_pack` | 读取匿名店铺/账户引用、最新计划聚合指标、证据哈希和本地护栏；不返回网页原文、凭证或明细数据 |
| `submit_ai_proposal` | 提交严格 `DecisionProposalV1` 建议并接受本地账户、时效、证据和策略校验；上下文已变化时拒绝 |
| `get_ai_proposals` | 读取本地提案审计队列；所有结果固定为不可执行 |

MCP 客户端必须先调用 `get_ai_context_pack`，再让模型引用返回的 `context_id`、`context_hash`、`account_ref` 和证据字段生成提案。上下文最长保留到其经营证据过期；计划指标、账户或本地护栏变化后，旧提案不能提交。三个工具均固定返回 `execution_allowed=false`、`can_execute=false`，不能通过猜测旧工具名绕过。

## 已知限制

- 网页字段没有官方稳定契约，平台改版后可能需要更新选择器。
- 虚拟滚动表格只能读取浏览器实际渲染过的行，分页采集也设有上限。
- 登录过期、验证码和平台风控必须由用户手动处理。
- 网页经营数据不会定时抓取；所有巡查都需要用户点击触发。
- 定时日报需要本地 Agent 保持运行，并使用最近一次缓存数据。
- 当前诊断以确定性规则为主，建议执行前应回到官方后台核对口径。
