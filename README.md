# 店策 Agent：抖店 × 巨量千川经营副驾

[![Version](https://img.shields.io/badge/version-3.4.1-2563eb)](extension/manifest.json)
[![Browser](https://img.shields.io/badge/Chrome%20%7C%20Edge%20%7C%20360%20%7C%20QQ-MV3-16a34a)](BROWSER_SUPPORT.md)
[![License](https://img.shields.io/badge/license-MIT-f59e0b)](LICENSE)
[![Mode](https://img.shields.io/badge/data-local--first-7c3aed)](SECURITY.md)

**不申请开发者 API，也能把抖店和巨量千川网页数据变成运营每天真正能执行的任务。**

店策 Agent 是一个本地优先、默认不执行写操作的 Chromium 浏览器扩展与 AI Agent 数据桥，支持 Chrome、Edge、360 极速浏览器 X，并为 360 安全浏览器、QQ 浏览器、搜狗浏览器、联想浏览器等提供兼容包。它复用运营人员已经登录的抖店、巨量千川网页，在用户主动点击后采集可见经营数据，完成脱敏、本地保存、异常诊断，并生成千川调整建议、库存预警、直播/货架分析和每日经营报告。

> 当前版本：`v3.4.1 Beta`。在只读投放策略模拟器上增加可审计的策略决策单；运营选择保 ROI、均衡经营或谨慎增长后，系统记录当时的计划范围、影响预估与选择时间，但仍只允许逐计划授权执行。

## 为什么做这个项目

很多店铺没有开放平台 API 权限，但运营仍要每天在多个后台页面之间反复切换、复制数据、判断风险和写报告。常见问题包括：

- 数据散落在抖店、千川、精选联盟等不同页面，查看成本高。
- 运营看到指标，却不知道今天最该先处理哪三件事。
- 千川计划调整依赖经验，缺少统一的止损、观察和放量口径。
- 库存、投放、直播和货架各自优化，容易出现“流量放大但库存断货”。
- 日报花时间整理数字，却很难形成负责人、动作和验收标准。

店策 Agent 的目标不是再做一块复杂看板，而是把数据收拢成一个清晰闭环：

```text
用户点击巡查 → 网页采集与脱敏 → 本地快照与趋势 → 风险诊断
          → 今日三件事 → 分配负责人 → 执行 → 复盘验收
```

## 谁适合使用

| 角色 | 最关心的问题 | 店策 Agent 提供什么 |
| --- | --- | --- |
| 运营总管 | 今天先处理什么、谁负责、何时验收 | 跨岗位任务排序、负责人、证据和验收标准 |
| 千川投手 | 哪些计划止损、观察、换素材或放量 | 计划级建议、判断依据和安全边界 |
| 直播运营 | 直播间流量为什么没有转化 | 观看→商品点击→成交漏斗诊断 |
| 货架运营 | 曝光、点击、成交卡在哪一层 | 货架漏斗、搜索/推荐卡诊断和优化动作 |
| 商品运营 | 哪些商品缺货、库存还能卖几天 | 缺货、极低库存、低库存和可售天数预警 |
| 店铺负责人 | 每日经营结果和异常是否闭环 | 自动生成本地日报、趋势对比和任务状态 |

## 核心能力

### 1. 无 API 的手动全店巡查

- 复用用户已登录的抖店、千川和精选联盟网页，不读取 Cookie。
- 仅在点击“全店巡查”后运行，依次打开 18 类核心页面。
- 千川数据直接来自已登录的巨量千川后台，覆盖首页、商品推广、直播推广、直播大屏和视频库。
- 支持识别多个千川账号、分账号保存快照，并由用户选择本轮分析账号；账号不一致时停止千川采集，避免数据串号。
- 多账号场景默认使用“自动识别当前登录账号”：第一个成功读取的千川页面会锁定本轮账号并用于后续页面，不再复用上一次巡查账号；只有用户主动选择固定账号时才进行强一致性校验。
- 账号目录会过滤“店铺”“ID”“账户余额”等页面栏目误识别结果，并按店铺名称合并同一账号在不同千川页面产生的临时标识。
- 账号识别或全店巡查失败时，先访问一次目标千川标签页，再点击工作台右侧常驻的“同步千川”；系统优先读取最近访问的千川标签页，不校验历史账号，也不扫描其他页面。
- 千川入口使用官方根地址并保留旧首页回退；遇到 `ERR_FAILED` 或登录失效时停止采集并给出明确恢复提示，不再把浏览器错误页当作经营页面。
- 抖店与千川巡查使用彼此独立的后台标签页；标签页意外关闭时自动重建并重试当前任务，避免一个失效标签页导致全部千川页面连续失败。
- 巡查使用独立后台标签页，不操作用户原有页面；结束后自动关闭。
- 巡查结束生成数据体检单，展示账号、覆盖率、页面质量、读取行数和失败原因；失败页面可以单独重试，不必重新扫描全部页面。
- 对列表页尝试虚拟滚动并最多采集 5 页，同时记录行数、滚动次数和截断提示。
- 逐页记录成功、失败、数据质量和页面类型；失败页面自动重试一次。

### 2. 经营数据自动填写与本地历史

- 按 `数据源 + 页面类型` 保存快照，订单、商品、库存和计划数据不会互相覆盖。
- 默认保留 30 天脱敏历史，展示近 7 天核心指标变化。
- URL 自动移除查询参数和 hash，页面原始 DOM 不会落盘。
- 数据只发送到本机 `127.0.0.1:8765`，不依赖云端数据库。

### 2.1 可选的巨量千川官方 OAuth

- 已取得巨量千川开放平台资质的用户，可在工作台“官方 API 授权”中连接应用。
- App ID 可公开配置；App Secret 不应发到聊天、写入代码或提交 GitHub，只在本机输入。
- Windows 使用当前用户 DPAPI 加密 App Secret、Access Token 与 Refresh Token。
- 公网回调只转发一次性授权结果到 `127.0.0.1:8765`，不保存 App Secret、Token 或账号密码。
- 每次授权都校验随机 `state`，授权会话 15 分钟后失效；授权码只用于一次 Token 交换。
- 官方 API 与浏览器页面采集共存，后续共用账号目录、经营数据模型和执行护栏。

### 3. 千川计划调整方案

- 按计划明细给出止损、保持观察、素材优化和谨慎放量建议。
- 结合 ROI 目标、消耗门槛和转化表现展示判断依据。
- 使用“千川投手今日工作台”只展示必须处理、需要观察和具备放量条件的计划。
- 每条建议固定包含发现、判断、动作、调整范围、观察窗口和验收指标，并可加入今日任务持续跟踪。
- 预算方案以结构化操作草稿展示账号、计划 ID、当前值、目标值、证据时间和校验结果。
- 账号、计划 ID、当前预算、数据质量或新鲜度任一不足时，按钮会锁定并提示补齐数据；不会把未知预算错误兜底成暂停计划。
- “确认方案”仍只写入本机审计；只有另行启动执行前检查、完成页面回读并输入最终确认口令后，才允许受监督执行器提交单计划降低预算。
- 已确认方案会进入“投放影子执行”：用户在官方千川手动完成后主动标记，系统要求重新读取对应计划页面，并将最新预算与确认目标进行核验。
- 影子核验明确区分“等待人工执行、等待重新读取、回读已匹配、页面尚未变化、检测到其他修改”；用户声明不等同于插件执行成功。
- 隐私模式不会保存原始计划 ID；系统将其转换为不包含原文、跨页面稳定的本地代号，用于关联同一计划的确认方案和后续回读。

### 4. 库存预警

- 识别缺货、极低库存和低库存商品。
- 在数据允许时估算预计可售天数。
- 把库存风险与直播、货架和投放任务放在同一优先级队列中。

### 5. 直播与货架数据分析

- 分析店铺直播和千川直播大屏的观看→商品点击→成交漏斗。
- 分析货架曝光→点击→成交漏斗。
- 输出风险解释、建议动作、负责人和复查指标，而不只展示数字。

### 6. 千川视频库与直播引流素材分析

- 直接读取巨量千川视频库，不再把视频库误识别为计划页。
- 按消耗、ROI、成交、素材评估和测试覆盖识别高消耗低转化、高潜、可复制和未测试素材。
- 从直播运营角度检查开场钩子、商品卖点、直播利益点和进房承接，并生成素材测试矩阵建议。
- 所有建议保持只读，不上传、删除或修改千川视频。

### 7. 运营总管与每日经营报告

- 总管、货架、直播、投放、商品五种岗位视图。
- 岗位和班次会保存在当前浏览器；支持日常经营、开播前、直播中、下播复盘四套标准动作模板，并按天记录完成状态。
- 首页最多展示 3 个当日必做事项，降低信息负担。
- 任务支持待处理、进行中、待观察和已完成状态。
- 可立即生成 Markdown 日报，也可按设定时间使用最近一次缓存数据生成日报。
- 日志可选“默认经营日报、老板简报、运营交接日志、自定义模板”；没有特殊要求时直接使用默认模板。
- 自定义模板支持 `{{date}}`、`{{headline}}`、`{{summary}}`、`{{top_tasks}}`、`{{plans}}`、`{{inventory}}`、`{{scan_status}}` 占位符。
- 可连接飞书或钉钉自定义机器人，先保存并测试，再选择“生成并发送”；也可开启定时日报自动发送。
- **定时日报不会触发网页巡查**；需要最新数据时，运营先手动点击巡查。

### 飞书 / 钉钉连接，只需 3 步

不需要申请开发者 API。只要在群聊里添加“自定义机器人”，复制机器人 Webhook，粘贴到工作台并点击“保存并测试”。

1. 在目标群聊中添加自定义机器人。
2. 安全设置建议使用关键词 `店策 Agent`，然后复制 Webhook。
3. 打开工作台的“飞书 / 钉钉通知”，粘贴 Webhook，点击“保存并测试”。

飞书操作以[飞书自定义机器人使用指南](https://open.feishu.cn/document/ukTMukTMukTM/ucTM5YjL3ETO24yNxkjN?lang=zh-CN)为准；钉钉操作以[钉钉自定义机器人接入说明](https://open.dingtalk.com/document/orgapp/custom-robot-access)为准。Webhook 相当于群机器人的发送密码，只保存在本机 `bridge/data/integrations.json`，页面不会回显完整地址，也不要把它提交到 GitHub 或发给其他人。

## 产品原则与安全边界

| 原则 | 当前实现 |
| --- | --- |
| 用户掌控 | 所有网页巡查均由用户点击触发 |
| 默认不执行 | 普通确认不写页面；受监督执行器仅在二次确认和全部闸门通过后降低单计划预算 |
| 最少采集 | 只读取经营指标和允许的表格字段，不保存整页 DOM |
| 本地优先 | 快照、历史、任务和报告保存在用户电脑 |
| 建议可解释 | 每个建议尽量包含证据、动作、安全边界和验收指标 |
| 人工确认 | 草稿确认与真实执行分离；真实执行需要最终口令、60 秒单次授权和执行后回读 |

详细安全说明见 [SECURITY.md](SECURITY.md)。

## 系统架构

```text
抖店 / 巨量千川 / 精选联盟已登录网页
                    │
                    ▼
Chromium 扩展（手动巡查、采集、脱敏、状态、独立工作台）
                    │  仅 http://127.0.0.1:8765
                    ▼
本地 Companion Service（快照、历史、任务、诊断、报告）
                    │
                    ├── 独立经营工作台标签页
                    └── MCP stdio（Codex / Claude Desktop / Cherry Studio 等）
```

## 快速开始

### 1. 下载项目

```bash
git clone https://github.com/3132882323-cyber/douyin-agent.git
cd douyin-agent
```

也可以在 GitHub 页面点击 `Code → Download ZIP` 后解压。

### 2. 安装浏览器扩展

Windows 小白用户推荐直接双击根目录的 `install_dian_agent.bat`。它会启动本地 Agent、设置登录自动启动，并同时打开浏览器扩展管理页和正确的 `extension` 文件夹。由于 Chromium 的安全限制，最后仍需人工点击一次“加载已解压的扩展程序”并选择该文件夹。

项目提供两个浏览器包：

- 现代浏览器版：Chrome 116+、Edge、360 极速浏览器 X 等较新 Chromium 浏览器。
- 多浏览器兼容版：360 安全浏览器、QQ 浏览器、搜狗浏览器、联想浏览器等较旧 Chromium 内核。
- 两个版本点击扩展图标都会先打开轻量哨兵，需要深入分析时再进入独立经营工作台。

Windows 用户双击 `build_browser_packages.bat`，生成 `dist/dian-agent-modern` 和 `dist/dian-agent-compatible`。随后：

1. 打开浏览器的扩展管理页面。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择对应的生成目录。
5. 将“店策 Agent”固定到工具栏。

也可以在 Chrome/Edge 中直接加载项目的 `extension` 文件夹。安装成功后扩展详情应显示版本 `3.0.1`。首次安装会打开轻量引导页；点击工具栏图标先进入轻量哨兵，需要深入分析时再打开完整工作台。360、QQ、搜狗等双核浏览器访问抖店和千川时必须使用“极速模式”，不能使用 IE 兼容模式。

完整浏览器矩阵和故障处理见 [浏览器适配说明](BROWSER_SUPPORT.md)。

### 3. 启用本地 Agent 自动启动

Windows 用户首次使用时双击：

```text
bridge/enable_autostart.bat
```

脚本会创建独立的 Python 运行环境、安装依赖、立即启动本地 Agent，并将其加入当前用户的 Windows 登录启动项。以后登录 Windows 后无需再次手动启动。

随后访问 <http://127.0.0.1:8765/health>。看到 `"status": "ok"` 即表示本地服务正常。安装程序会同时创建登录启动快捷方式和每 5 分钟检查一次的本地保活任务；Agent 因休眠、更新或异常退出后会自动恢复。需要临时手动启动时仍可运行 `bridge/start_bridge.bat`；需要关闭自动启动时运行 `bridge/disable_autostart.bat`。

> 抖店和千川账号登录由平台官方登录页面及当前浏览器登录状态管理。本项目不会保存账号密码，也不会绕过验证码或平台风控。

### 4. 开始第一次巡查

1. 在已安装扩展的浏览器中登录抖店和巨量千川。
2. 点击扩展图标，浏览器会打开独立经营工作台；重复点击会回到已有工作台。
3. 在工作台点击“全店巡查”获取多页面数据；如果千川巡查失败，先访问一次目标千川账号页面，再回到工作台点击右侧常驻的“同步千川”。按钮会复用最近访问的千川标签页并保存为后续巡检入口。
4. 直接在工作台查看今日三件事、千川建议、库存风险和直播/货架分析。
5. 在策略设置中填写 ROI 目标、消耗判断门槛和低库存阈值。

已申请官方 API 的用户还可以展开顶部“官方 API 授权”，在本机填写 App Secret 后点击“授权千川账号”。授权成功后，开放平台的“授权管理账号”列表才会出现对应账号。

## MCP 接入

本地 Agent 可以把已脱敏数据和诊断结果提供给支持 MCP 的 AI 客户端。

```json
{
  "mcpServers": {
    "dian-agent": {
      "command": "python",
      "args": [
        "C:\\path\\to\\douyin-agent\\bridge\\server.py"
      ]
    }
  }
}
```

## 已知限制

- 网页字段没有官方稳定契约，平台改版后可能需要更新选择器。
- 虚拟滚动表格只能读取浏览器实际渲染过的行，分页采集也设有上限。
- 登录过期、验证码和平台风控必须由用户手动处理。
- 网页经营数据不会定时抓取；所有巡查都需要用户点击触发。
- 定时日报需要本地 Agent 保持运行，并使用最近一次缓存数据。
- 当前诊断以确定性规则为主，建议执行前应回到官方后台核对口径。
